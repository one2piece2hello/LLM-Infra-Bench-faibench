# 正确性任务：分层存储引擎与跨层一致性（tiered storage I/O）

## 你拿到什么

一个基于 Python 的运行环境。评测器会导入你实现的模块，并驱动其中的一个类：**分层存储引擎**
`TieredStore`。这是一道**分层存储 / 迁移 / 跨层一致性**正确性题：你要实现一个带**容量上限的热层
（hot tier，内存）** 覆盖在一个**冷层（cold tier，作为权威持久副本）** 之上的键值存储，支持按大小驱动
的 LRU 驱逐、可断点续传的分段迁移（segmented transfer）与完整性校验，以及在任意访问顺序与并发交错下
都与参考模型一致的跨层读语义。语义对齐真实系统：seaweedfs 的 volume-tier（本地缺失时从远端装载）、
RocketMQ 的 `TieredMessageStore`（本地 commitlog 与远程 tier 协调读取）、kafka 的 `RemoteLogManager`
（分层日志段上传 / 元数据 / 远程读取）、etcd 的 `scheduleCompaction`（分批处理、全部完成才落 finished
标记）、以及 redis/valkey 的多段 AOF manifest（base/incremental/history + 原子切换）。

## 必须实现的 API（类名 / 方法名 / 签名需完全一致）

### `class TieredStore`

- `__init__(self, hot_capacity, cold_fetch_fn=None)`：
  - `hot_capacity`：热层中**所有 value 字节数之和**的上限。
  - `cold_fetch_fn`（可选）：`callable(key) -> bytes`，用于从冷层拉取一个仅存在于冷层的对象；给出时，
    对"热层未命中但冷层存在"的 key，必须调用它取回数据（并且并发拉取需**合并**，见下）。
- `put(self, key, value)`：`value` 为 `bytes`。把 `key=value` **持久写入冷层**（冷层是权威副本），同时插入
  热层并标记为最近使用；随后**按大小驱逐**：当 `sum(热层 value 字节) > hot_capacity` 时，反复驱逐**最久
  未使用（LRU）**的 key，直到不超限（被驱逐的 key 的权威副本仍在冷层）。
- `get(self, key)`：返回 `key` 的当前值（`bytes`），不存在返回 `None`。
  - 热层命中：标记为最近使用并返回；
  - 热层未命中但冷层存在：从冷层取回并放入热层（标记最近使用，可能触发驱逐）后返回；
  - 冷热都没有：返回 `None`。
  - **并发合并**：多个线程同时 `get` 同一个"仅冷层"的 key 时，必须**合并（coalesce）**，使 `cold_fetch_fn`
    被调用的次数尽量少，且所有并发调用者观察到**同一个值**。
- `seed_cold(self, key, value)`：把一个值登记到**远端冷存储**（仅通过 `cold_fetch_fn` 可达；**不放入热层，
  也不放入本地已缓存的冷副本**）。随后对该 key 的首次 `get` 未命中热层时，必须经 `cold_fetch_fn(key)` 取回。
- `hot_size(self)`：返回热层中当前所有 value 字节数之和（用于容量不变式检查）。
- `in_hot(self, key)`：返回 `key` 当前是否驻留在热层。
- `transfer(self, key, segment_size, sink=None, resume_from=None)`：把 `key` 的对象从冷层**按固定大小分段**
  取出，逐段写入 `sink`（通过 `sink.write_segment(index, data, crc)`）。
  - `segment_size` **必须 > 0**，否则抛异常；`key` 不存在时必须**抛异常或返回 `None`**。
  - 若给出 `resume_from`（一个"已收到的分段索引"清单），你**必须跳过这些索引，不得重发**（断点续传，
    manifest 驱动）。
  - 若 `write_segment` 抛出"坏分段"信号（crc / 损坏），你**必须重新取该分段并重发**（绝不能跳过或静默接受）。
  - 返回对象的总分段数。

## 正确性提示（最容易踩坑的地方）

- **LRU + 大小驱逐**：热层容量是"字节和"不是"条目数"；`get` 命中与冷层取回都要"touch"为最近使用；驱逐
  从最久未使用端开始，直到满足容量不变式。任何时刻 `hot_size() <= hot_capacity`（除非单个对象本身超容量，
  此时它应能通过冷层被读到）。
- **冷层是权威副本**：被驱逐出热层的 key 仍必须能通过 `get` 读到**字节完全一致**的值（经冷层取回）。
- **断点续传**：`resume_from` 给出的分段索引不能重发；续传后拼装出的对象必须与原对象**校验和一致**。
- **完整性**：`write_segment` 抛"坏分段"时，必须**重取并重发**该分段，最终拼出的对象校验和必须正确。
- **合并取回**：多个线程读同一"仅冷层" key 时，只应触发少量 `cold_fetch_fn`（用"首个线程负责取、其余等待
  复用"的事件 + 锁模式），且所有线程返回值一致。
- **并发读写**：写线程不断 `put` 时，读线程读到的值必须是**确实被写过的某个值**（不允许撕裂或幻读），
  所有写完成后每个 key 都必须能读到字节一致的值。
- **分批驱逐原子性**：一次驱逐批次要么完整完成（key 从热层消失、仍在冷层可读），要么保持不变——不得出现
  "热层超容量的半驱逐"中间态。
